# DanaSafe V9.5.4 — Release audit

## Scope
Single-purpose correction of radar-time origin for ETA/closest approach/current distance and 10/30/60-minute QPE. Source base: V9.5.3 LOCATION SEARCH AUDITED.

## Root cause confirmed
`track.latestCoordinate` belongs to `track.latestTimestamp` (or, as fallback, the snapshot `radarTimestamp`). The production evaluator previously treated that coordinate as t=0 at the user's current time. With a stale radar frame, ETA and QPE therefore started from an old atmospheric position.

## Implemented correction
1. Preserve baseline `NowcastEvaluator.evaluate(...)` and `best(...)` unchanged for regression comparison.
2. Add `evaluateFreshnessAdjusted(...)` / `bestFreshnessAdjusted(...)`.
3. Compute physical age as `max(0, userNow - track.latestTimestamp)`, falling back to snapshot radar timestamp if needed.
4. Advance the track centroid by `velocityEast/North * age` before computing current distance, closest approach and ETA.
5. Reduce the remaining future horizon by the same age so total extrapolation never exceeds the original nowcast horizon from the observed track position.
6. Start QPE integration from the freshness-adjusted centroid and stop accumulating after the same validity ceiling.
7. Route app model, UI precipitation forecast and Siri/AppIntents through the freshness-adjusted path.
8. Leave hydrology, ECRINS, MapKit place search, reservoirs and radar-system generation untouched.
